## 地图背景图片修复：全屏适配

### 问题
用户反馈 map2.png（2560×1440，16:9）没有完全进入视口镜头，地图部分被裁剪。

### 根因
1. **stretch_mode = 6** → STRETCH_KEEP_ASPECT_COVERED，会放大图片填满区域并裁剪超出部分
2. **缺少 expand_mode** → 默认值 0（KEEP_SIZE），TextureRect 最小尺寸锁死在纹理原始尺寸 2560×1440，远超视口

### 修复
- `expand_mode = 1`（IGNORE_SIZE）：忽略纹理原始尺寸，让容器控制大小
- `stretch_mode = 0`（STRETCH_SCALE）：等比缩放到填满容器

两个参数配合后，map2.png 将完整适配 1920×1080 视口无裁剪。

## 致命 Bug 修复：UID 数据库不匹配导致整个场景树塌缩

### 问题诊断
用户反馈 `_enemy.died` null instance 错误，游戏无法运行。

通过 Godot 日志（`%APPDATA%/SlayTheSpire2/logs/godot.log`）发现级联故障：
```
WARNING: ext_resource, invalid UID: uid://bu32mprrcfl8p → 退回到文本路径
WARNING: Parent path './EnemyArea' for node 'Enemy' has vanished
ERROR: Node not found: "EnemyArea/Enemy" (relative to "/root/BattleScene")
ERROR: Node not found: "HandArea"
SCRIPT ERROR: Invalid access to property or key 'died' on a base object of type 'null instance'.
```

### 根因
**手动创建的 `.gd.uid` 文件与 Godot 内部 UID 数据库不匹配。** Godot 4.4+ 的 UID 系统不仅仅依赖 `.uid` 文件内容，还有内部数据库（可能是 `.godot/` 目录下的缓存）。手动写入的 UID 值虽然格式正确，但不在 Godot 的内部映射中，导致被判定为 `invalid UID`。

当 ext_resource 的 UID 无效时，Godot 退回到文本路径但加载过程被破坏，导致后续父节点"消失"，整个节点树塌缩。

### 修复步骤
1. **删除所有手动创建的 `.uid` 文件**（8 个）：
   - `scenes/combat/battle_scene.gd.uid`
   - `scenes/combat/hand_area.gd.uid`
   - `scenes/combat/enemy.gd.uid`
   - `scenes/cards/battle_card.gd.uid`
   - `src/systems/card_effect.gd.uid`
   - `src/autoloads/event_bus.gd.uid`
   - `src/autoloads/battle_manager.gd.uid`
   - `src/resources/card_data.gd.uid`

2. **移除 TSCN 中所有脚本的 ext_resource UID**，改用纯路径引用：
   - `battle_scene.tscn`：4 个 Script 的 uid 移除 + scene 头 uid 移除
   - `battle_card.tscn`：1 个 Script 的 uid 移除

3. **添加防御性 null 检查**到 `battle_scene.gd`：
   - `_enemy`、`_end_turn_button`、`_card_effect` 使用前检查
   - `_enemy_action()`、`_start_next_turn()`、`_on_card_played()` 加 null guard

### 经验教训
- **永远不要手动创建 `.uid` 文件** — 让 Godot 编辑器自己生成
- **不要手动在 TSCN 中写 uid 值** — 只用 `path` 属性，Godot 会自动关联 UID
- Godot 的 UID 系统有内部一致性校验，手动写入的值即使格式正确也可能无效

## 修复 2 个致命运行时错误 + Godot 缓存损坏清理

### 错误诊断
| # | 错误 | 调用次数 | 根因 |
|---|------|---------|------|
| 1 | `Node not found: "DiscardPilePanel"` | 28次 | `_update_pile_empty_style()` 用 `$DiscardPilePanel` 运行时查找，而非 @onready 预解析 |
| 2 | `BattleCard` 找 `NameBG` 失败 | 28次总 | **`.godot/uid_cache.bin` 损坏！** BattleCard 被错误嵌套到敌人 HPLabel 路径下 |

### 错误 2 关键发现
BattleCard 的 `_ready()` 报错路径：
```
/root/BattleScene/EnemyArea_Enemy_EnemyPanel_HBox_VBox_HPContainer#HPLabel/BattleCard
```
BattleCard 应该在 HandArea 下！出现在敌人 HP 标签中 = **Godot 缓存错乱**。

### 修复内容

**battle_scene.gd (Error 1):**
- 新增 `@onready var _discard_pile_panel: PanelContainer = $DiscardPilePanel`
- `_setup_ui_styles()`: `$DiscardPilePanel as PanelContainer` → `_discard_pile_panel`
- `_update_pile_empty_style()`: 同上替换
- 消除每次调用都做 O(n) 节点查找的性能问题

**battle_card.gd (防御性):**
- `_ready()` 新增父节点路径打印：`parent=%s, card_data=%s`
- 下次运行时控制台会明确显示每张 BattleCard 被添加到哪个父节点

**hand_area.gd (防御性):**
- `_on_card_drawn()` 新增父节点名验证：`parent_node=%s (self=%s)`
- 确认 add_child() 的目标确实是 HandArea

**Godot 缓存清理 (Root Cause Fix):**
- 删除 `.godot/uid_cache.bin`（UID 映射缓存 → 重建）
- 删除 `.godot/global_script_class_cache.cfg`（全局类缓存）
- 删除 `.godot/filesystem_cache10`（文件系统缓存）
- 删除 `.godot/filesystem_update4`
- 删除 `.godot/editor_script_doc_cache.res`

### 为什么 28 个错误共享同一个根因
`uid_cache.bin` 是 Godot 4 的 UID ↔ 文件路径映射表。损坏后：
- `ExtResource("5_card_scene")` 可能被映射到错误的 PackedScene
- `$DiscardPilePanel` 在损坏的树中找不到节点
- 两个"看起来不相关"的错误 → 同一条损坏的缓存行

### 用户需执行
1. 在 Godot 编辑器中**关闭并重新打开项目**（让 Godot 重建缓存）
2. 按 F5 运行 → 控制台应显示每张 BattleCard 的父节点路径
3. 确认 BattleCard 都在 HandArea 下，不再是敌人 HPLabel
