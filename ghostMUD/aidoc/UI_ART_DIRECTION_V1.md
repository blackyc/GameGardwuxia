# UI Art Direction V1

版本：V1.0  
日期：2026-07-10  
适用范围：ghostMUD 全局 UI 美术方向、江湖页面 V1 控件风格板、后续 Figma / CSS / 文生图执行约束  
当前状态：方向冻结，不等于所有页面视觉方案冻结

## 1. 总纲

ghostMUD 的 UI 方向定义为：

> 淡墨纸屏，暗骨 MUD。

玩家看到的应是一张被江湖事件激活的水墨纸屏，而不是一张盖着按钮的国风插画；底层信息组织必须保留传统文字 MUD 的清晰层级、行动回声和命令台感。

通俗说：

- `image1 / image2` 提供纸面、水墨、标题牌、按钮质感和手机版疏密关系。
- `image3 / image6 / image7` 提供 MUD 信息骨架、低装饰、强对比、事件回声和抽象空间感。
- `image5 / image8` 提供地图和房间气氛，但不直接承担常规文字阅读层。
- `dreamina` 提供特殊情绪横幅参考，只能用于少数高强度节点。

本项目的 UI 不追求“每一屏都是一张漂亮图”。本项目追求的是：

1. 文字可读。
2. 行动明确。
3. 日志有回声。
4. 背景有气味但不抢戏。
5. 日常克制，关键时刻升格。

## 2. 最高优先级

UI 设计优先级如下，越靠前越不可牺牲：

1. 文字可读性。
2. MUD 行动链路清晰。
3. 房间 / NPC / 日志三层语义不混。
4. 移动端单手操作可控。
5. 江湖水墨气质。
6. 局部美术装饰。
7. 动效和奇观。

任何 worker、AI、Figma 组件或 CSS 修改，只要牺牲 1-3 项来换取“更好看”，都视为越界。

## 3. 核心气质

### 3.1 正向气质

应该靠近：

- 旧纸、宣纸、淡墨、水渍、远山、竹影、雾气。
- 早期文字 MUD 的冷静记录感。
- 近年手游的美术完成度，但不使用网游商城式堆叠。
- 按钮少而明确，控件像贴在纸上的江湖令、名帖、木牍。
- 留白有重量：纸纹、墨线、边界、山水切片共同撑住空白。

### 3.2 反向禁区

禁止靠近：

- 大面积纯白网页卡片。
- 玻璃拟态、现代 SaaS 卡片、过度圆角。
- 过亮、过浅、过灰导致的“泛白”。
- 背景图直接铺满文字区，导致叙事文本漂浮在海报上。
- 所有页面都套同一种水墨卡片。
- 普通房间频繁弹出全图事件页，破坏 MUD 连续移动感。
- dreamina 类金属红框滥用于日常按钮或普通对话。

## 4. 参考图转译

### 4.1 `image1 / image2`：手机版江湖页面正向参考

可借鉴：

- 顶部房间名牌居中，有仪式感。
- 背景与内容区域存在明确疏密关系。
- 中部叙事文本清楚，大字号、深色、可阅读。
- NPC 人名按钮是独立小方框，不承载人物描述。
- 底部功能按钮具有国风图形感。
- 最近日志 / 警示文本使用朱红，语义强。

不可照搬：

- 不复制全部数值栏布局。
- 不把所有字号都放大到样机级别。
- 不让所有功能按钮都变成大菱形。
- 不把每个房间都做成同样完整插画页。

结论：`image1 / image2` 是江湖页面的纸面风格和疏密结构锚点。

### 4.2 `image3 / image6 / image7`：传统 MUD 骨架参考

可借鉴：

- 顶部只显示少量关键状态。
- 当前房间、出口、人物、操作按钮分层清楚。
- 日志位于底部，负责记录“你做了什么 / 世界回应了什么”。
- 人物先以名字出现，点击后再展开交互。
- 颜色少，每种颜色都有语义。
- 抽象地图 / 节点关系让玩家理解空间，不依赖全景绘制。

不可照搬：

- 不直接使用纯黑底作为江湖主页面常态。
- 不复制早期 MUD 方格移动，因为 ghostMUD 当前路径系统和功能结构不同。
- 不把按钮堆在画面中央遮挡主叙事。

结论：这些图不是外观主参考，而是信息架构主参考。ghostMUD 的“骨头”应来自它们。

### 4.3 `image5 / image8`：地图背景参考

可借鉴：

- 用作房间气氛、地标图、事件插图。
- 作为顶部 / 底部背景切片。
- 用于特定 room 的短暂事件页或首次进入地标演出。

风险：

- 直接铺满主界面会污染文字区。
- 雾气和建筑边缘会与按钮、正文争夺注意力。
- 情绪过强的背景不适合长期复用。

结论：背景图是“气味”，不是常规 UI 的主体。

### 4.4 `dreamina`：特殊横幅参考

可借鉴：

- 战斗结果。
- 受伤 / 濒死。
- 灵修污染。
- 血契 / 诡异线索。
- Boss 前兆。
- 门派禁令。

禁止：

- 不用于普通 NPC 名牌。
- 不用于普通房间标题。
- 不用于普通对话框。
- 不作为主界面日常按钮风格。

结论：dreamina 是异物感组件，只在高情绪节点出现。

## 5. 背景策略

### 5.1 常规房间

常规房间不使用全图铺底。推荐结构：

```text
顶部 12-15%：背景切片 + 房间名牌
中部 60-65%：纸底 + 场景叙事 + NPC 名牌 + 交互
底部 20-25%：背景切片 / 雾山 / 纸底日志
```

关键规则：

- 中部主叙事区以纸底为主，不让复杂背景进入阅读层。
- 纸底不能是纯白，必须有旧纸色、轻纸纹、墨线边界。
- 顶部和底部可以使用房间背景图切片，承担气氛。
- 背景切片应服务语义：顶部表示“我在哪里”，底部承接“刚刚发生了什么”。

### 5.2 地标房间

地标房间可以首次进入时短暂展示地标图，之后回到常规房间 UI。

适用：

- 问剑峰山门。
- 落月山庄。
- 藏经阁。
- 金牛武馆。
- 夜间酒肆。
- 关键副本入口。

规则：

- 地标图默认 `showOnce: true`。
- 再次进入不重复弹全图，只保留日志回声或小型地标标记。
- 地标展示不得阻断基础移动超过必要时间。

### 5.3 遭遇事件

遭遇事件可采用类似“事件页”结构：

```text
上方 35-45%：事件插图
下方 55-65%：纸底描述 + 选项
```

适用：

- 奇遇。
- 灵修异象。
- 隐藏 NPC 首遇。
- 听见井中低语。
- 发现血字。
- 苏小棠突然停步。
- 满足特殊条件后可见的诡异房间。

规则：

- 事件完成后回到常规房间 UI。
- 不要让普通房间移动频繁触发事件页。
- 事件页是演出，不是默认房间容器。

### 5.4 异界 / 灵修 / 梦境

异界、灵修、梦境可以临时破坏常规 UI，但必须被视为“系统异常态”。

允许：

- 全屏图。
- 暗化。
- 墨雾。
- 文字错位。
- 纸面破碎。
- 2D / SVG / Canvas 奇观。

约束：

- WebGL / Three.js 不进入关键路径。
- 核心叙事情绪必须有 2D 降级版本。
- 异常态结束后恢复常规 UI 文法。

## 6. 江湖页面 V1 方向

江湖页面是当前唯一已进入可执行阶段的页面。其他页面不得直接套用江湖页面方案。

### 6.1 三层语义

江湖页面固定三层：

1. 房间名 / 地点身份。
2. 主叙事 / NPC / 操作。
3. 最近日志 / MUD 回声。

三层不得混用：

- 房间描述不写 NPC 长台本。
- 最近日志不写长篇场景叙事。
- NPC 名牌不承载人物描述。
- 正式对话进入“水墨言路”。

### 6.2 顶部房间名

要求：

- 房间名居中。
- 使用牌匾 / 纸牌 / 墨框。
- 背景可以使用远山、月、竹影、屋檐切片。
- 返回、状态等按钮靠边，不能抢房间名。

避免：

- 大面积空白标题栏。
- 现代 navbar。
- 房间名过小。

### 6.3 主叙事区

要求：

- 主要内容为旧纸底。
- 场景叙事控制在 3-5 行。
- 使用深墨字，行高充足。
- 背景纹理只轻微存在。

避免：

- 纯白卡片。
- 灰字过浅。
- 叙事文本占满整个主区。
- 把对话台本塞入房间描述。

### 6.4 NPC 呈现

NPC 默认以“小名牌”出现。

普通状态：

- 每个 NPC 一个独立小方框。
- 宽度随名字内容，不横向铺满。
- 不显示人物描述。
- 不显示长台词。

选中状态：

- 在同一区域展开人物详情。
- 描述最多 2-3 行。
- 操作按钮显示：交谈、观察、送礼、切磋。
- 条件不足要显示原因，不得只置灰。

特殊 NPC：

- 关键 NPC：可有细金边或小卷轴标记。
- 引路 NPC：可有“随行”状态标记。
- 诡异 NPC：可轻微破坏常规名牌，如墨渗、朱砂点，但不可影响可读性。

### 6.5 苏小棠 / 引路 NPC

苏小棠属于“随行引路 NPC”，不是普通房间 NPC。

规则：

- 她应随教程阶段移动到多个房间。
- 每个房间可以有不同短台本。
- 台本不应塞进主叙事长文本。
- 可通过“同行提示 / 引路气泡 / 最近日志”轻量呈现。
- 到指定 room 后触发分离台本，如“走累了，剩下的你自己转悠吧！”。
- 分离后从随行状态移除，后续按普通 NPC 或剧情 NPC 规则出现。

### 6.6 最近日志

最近日志是 MUD 控制台，不是第二个剧情正文区。

写法：

- “你进入了【山门】。”
- “你看向值星弟子。”
- “苏小棠跟着你穿过山门。”
- “值星弟子似乎不愿多说。”

不写：

- 大段抒情。
- 正式对话完整台本。
- 房间背景细节重复描述。

视觉：

- 字号小于主叙事。
- 行距更紧。
- 默认只露最近几条。
- 系统提示灰黑，关键提示朱红或暗金。

## 7. 页面隐喻总表

以下是全游戏页面的方向占位，不等于已冻结方案。每个页面在进入 Figma 前都必须单独讨论。

| 页面 | 视觉隐喻 | 状态 |
| --- | --- | --- |
| 江湖页面 | 纸上 MUD / 房间游历 | 已定 V1 方向 |
| 武学页面 | 经脉谱 / 招式谱 / 行功盘 | 未详细讨论 |
| 地图页面 | 山河折图 / 节点游历 | 未详细讨论 |
| 人物页面 | 身帖 / 命簿 / 江湖档案 | 未详细讨论 |
| 物品页面 | 行囊 / 匣柜 / 账册 | 未详细讨论 |
| 战斗页面 | 战报 / 气机对冲 / 回合命令台 | 未详细讨论 |

### 7.1 武学页面边界

不得简单做成现代技能列表。

后续应探索：

- 经脉槽位。
- 行功战诀构筑。
- 招式之间的关系。
- 内功 / 身法 / 武技 / 诡异污染的不同视觉语法。

### 7.2 地图页面边界

不得只是大背景图加按钮。

后续应探索：

- 山河折图。
- 节点 / 路径 / 条件可见区域。
- 世界地图与副本房间分层。
- 隐藏房间的显现规则。

### 7.3 人物页面边界

不得只是属性表。

后续应探索：

- 身帖。
- 江湖身份。
- 关系记忆。
- 心性 / 修为 / 污染 / 门派身份。

### 7.4 物品页面边界

不得直接做现代背包格子。

后续应探索：

- 行囊。
- 匣柜。
- 账册。
- 任务道具、线索道具、装备、消耗品的视觉区分。

### 7.5 战斗页面边界

不得复用江湖页布局。

后续应探索：

- 双方状态。
- 战诀槽位。
- 行动队列。
- 战报日志。
- 气机变化。
- 可打断、可介入、可逃离等 MUD 战斗命令感。

## 8. 色彩规范 V1

颜色是语义，不是装饰。

| 用途 | 建议色 | 语义 |
| --- | --- | --- |
| 旧纸底 | `#E7E1D2` | 常规阅读底 |
| 冷纸青 | `#DCE5E0` | 夜景 / 山水房间底 |
| 深墨字 | `#1F2523` | 主文字 |
| 次级字 | `#5D625D` | 日志 / 辅助说明 |
| 灰墨边 | `#6E716A` | 常规边框 |
| 纸黄按钮 | `#E5D188` | 可行动作 |
| 按钮深边 | `#353A35` | 按钮轮廓 |
| 当前青 | `#4BB7B4` | 当前地点 / 当前态，少量使用 |
| 朱红 | `#A7352E` | 警示 / 关键记忆 |
| 暗金 | `#A57B2C` | 稀有 / 重点 / 关键 NPC |
| 禁用灰 | `#B8B3A6` | 不可用 |

强制要求：

- 主文本不得使用浅灰。
- 朱红不得滥用于普通装饰。
- 当前青不得大面积铺底。
- 纸黄按钮必须有深边或墨线，否则会泛白。

## 9. 字体规范 V1

目标：清晰、深、稳定、可读。

建议层级：

| 层级 | 用途 | 方向 |
| --- | --- | --- |
| 房间名 | 地点标题 | 楷体 / 书法感，较大，有轻描边 |
| 主叙事 | 场景描述 | 宋体 / 仿宋方向，深墨字 |
| NPC 名牌 | 人物名 | 黑字或白字描边，短而有力 |
| 操作按钮 | 行动 | 较粗，必须可点感明显 |
| 最近日志 | 控制台回声 | 更小、更紧、更冷静 |

禁止：

- 为了“古风”使用难读字体。
- 主叙事字过细。
- 日志和正文同字号同颜色，导致语义混乱。
- 文生图直接生成中文 UI 字。

## 10. 控件规范 V1

### 10.1 NPC 名牌

状态：

- 普通。
- 选中。
- 关键。
- 引路。
- 条件隐藏。
- 条件可见但不可交互。

要求：

- 小而明确。
- 不横向铺满。
- 不承载描述。
- 点击后展开详情卡。

### 10.2 行动按钮

包括：

- 交谈。
- 观察。
- 送礼。
- 切磋。

状态：

- 可用。
- 禁用。
- 条件不足。
- 执行中。
- 选中 / hover / pressed。

强制：

- 禁用必须有原因。
- 切磋如果战斗系统已接入，不得无原因置灰。
- 可行动作使用纸黄，不能和背景混成一片。

### 10.3 菱形功能按钮

适用：

- 感知。
- 修行。
- 休憩。

约束：

- 不要让所有功能都变成菱形。
- 不要过大抢占主叙事。
- 图形感可保留，但必须服务常用操作。

### 10.4 水墨言路

适用：

- 正式对话。
- 关键 NPC 交谈。
- 分支选择。
- 线索划线。

要求：

- 与江湖页面同一视觉语言，但仪式感升格。
- 可回顾当前对话。
- 分支选项固定物理区域，防止误触。
- 长台词查看不得引发选项布局下推。

### 10.5 事件页

适用：

- 奇遇。
- 地标首见。
- 灵修异象。
- 重要剧情节点。

要求：

- 上图下文。
- 完成后回到常规房间 UI。
- 不作为普通 room 默认形态。

## 11. 文生图使用协议

文生图适合生成“无文字素材”，不适合生成最终 UI。

### 11.1 可以生成

- 房间背景。
- 顶部远山切片。
- 底部近景切片。
- 纸纹。
- 墨线边框。
- 旧纸按钮内衬。
- 事件插图。
- 战斗横幅材质。
- 灵修污染纹理。

### 11.2 禁止生成

- 带中文文字的完整 UI。
- 最终按钮文字。
- 复杂可交互页面。
- 需要精确布局的界面。

### 11.3 推荐提示词结构

生成背景时使用：

```text
水墨国风, 宣纸纹理, 低饱和青灰, 留白充足, 适合文字游戏背景,
顶部有远山/竹影/屋檐, 中部大面积干净纸面, 底部近景山石/雾气,
no text, no UI, no logo, no characters, mobile vertical composition
```

生成事件插图时使用：

```text
水墨国风事件插图, 江湖/修真氛围, 低饱和, 强留白,
画面上半部有明确事件主体, 下半部可留给文字面板,
no text, no UI, no logo, mobile vertical composition
```

生成控件材质时使用：

```text
old xuan paper texture, ink border, subtle water stain, low contrast,
game UI material, no text, no icon, transparent or clean background
```

### 11.4 生成后处理

所有文生图素材进入项目之前必须经过：

1. 可读性测试。
2. 移动端裁切测试。
3. 灰度测试。
4. 和纸底 / 墨字 / 按钮的叠加测试。
5. 文件大小压缩。

## 12. Figma 使用协议

Figma 的目标不是画漂亮大稿，而是建立可执行约束。

### 12.1 第一阶段：变量

必须先建立：

- Color tokens。
- Typography tokens。
- Spacing tokens。
- Border tokens。
- State tokens。

### 12.2 第二阶段：控件板

先做控件，不做全页面大稿。

必做组件：

- RoomTitlePlaque。
- SceneTextPanel。
- NpcNameChip。
- NpcDetailCard。
- ActionButton。
- DiamondActionButton。
- RecentLogLine。
- DialogueShell。
- DialogueChoice。
- EventPanel。
- AlertBanner。

### 12.3 第三阶段：变体

每个核心组件必须至少有：

- Default。
- Selected。
- Disabled。
- ConditionLocked。
- Key。
- Guide。
- Danger。

### 12.4 第四阶段：CSS 映射

Figma 组件必须映射到代码类名。

示例：

| Figma 组件 | CSS class |
| --- | --- |
| RoomTitlePlaque | `.location-banner` |
| SceneTextPanel | `.scene-description` |
| NpcNameChip | `.npc-chip` |
| NpcDetailCard | `.npc-detail-card` |
| ActionButton | `.npc-action-button` |
| DiamondActionButton | `.jianghu-action-button` |
| RecentLogLine | `.recent-log-line` |
| DialogueShell | `.dialogue-shell` |
| EventPanel | `.event-panel` |

worker 不得新增平行组件体系。新增组件必须先补 Figma 名称和 CSS 映射。

## 13. Worker 边界

worker 可以做：

- 按文档实现指定 CSS class。
- 按 Figma token 替换颜色、字号、边框。
- 调整已批准组件的状态样式。
- 添加 UI 自动验收。

worker 不可以做：

- 自行改变页面视觉隐喻。
- 把江湖页样式套到武学 / 地图 / 人物 / 物品 / 战斗页面。
- 把背景图铺满主叙事区。
- 把 NPC 名牌改成大横条。
- 把正式对话台本放回主叙事区。
- 用 dreamina 类横幅做普通按钮。
- 删除或改写人类设计文档。
- 修改 `aidoc/archive_*` 内的历史设计文档，除非任务明确要求。

## 14. 验收清单

任何 UI 大版本集成后，必须检查：

1. 中部主叙事是否仍清楚可读。
2. 页面是否出现泛白。
3. NPC 是否仍是小名牌。
4. NPC 描述是否只在点击后出现。
5. 正式对话是否进入水墨言路。
6. 最近日志是否仍是第三视角 MUD 回声。
7. 禁用按钮是否有原因。
8. 背景图是否没有喧宾夺主。
9. 移动端是否无文字溢出。
10. PC 端是否没有过度拉伸。
11. 新增控件是否有 Figma / CSS 映射。
12. 是否误改了未讨论页面。

## 15. 当前未决问题

## 16. 一句话执行标准

如果一个改动让 ghostMUD 更像“清晰、有回声、可长期阅读的江湖 MUD”，它大概率正确。

如果一个改动只是让截图更像“漂亮国风手游海报”，但削弱了文字、行动、日志和房间结构，它大概率错误。
