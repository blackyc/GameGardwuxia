### 偏差 1（P1）：`_applyStatusEffects` 仍直接读 `skill.shiguNum` 等旧字段名

方案要求："_applyStatusEffects 不直接读 skill.shiguNum 等旧字段，改读 skill.status.shigu"

实际代码（battle_async.js:980-1020）：
```js
if (skill.shiguNum > 0) { ... defenderStatus.shigu = stacks; }
if (skill.lieshangNum > 0) { ... defenderStatus.lieshang = stacks; }
```

**功能影响**：低。因为 `normalizeCombatSkill` 已经同步了 `shiguNum`（从 `duNum` 或 `status.shigu` 映射回来），所以数值不会出错。但方案的设计意图是让引擎只依赖 `skill.status.*`，避免未来归一化层改变同步行为时引擎断裂。

### 偏差 2（P2）：`getSkillCost()` 未被引擎使用

方案要求："`getBattleUIData()` 的 `mpEnough` 和 `mpGate.need` 都走 `getSkillCost(skill)`"

实际代码多处用 `sk.mana || 0`（第 361/443/611/673/1412 行），未调用 `getSkillCost()`。

**功能影响**：极低。归一化后 `sk.mana` 值正确。但未使用统一入口函数。

### 偏差 3（P2）：`calcSkillDamage` 实际调用点未传 `weaponAtk`

方案要求："`calcSkillDamage` 接收 `weaponAtk`"

实际：新增了 `calcSkillDamageWithWeapon()` 函数，但第 448 行仍调用 `calcSkillDamage(sk, attackerData.atk, ...)`。`weaponAtk` 在 `startCombat` 中已加到 `attackerData.atk`，所以数值结果正确，但不符合方案的设计意图。

### 偏差 4（P1）：`combatAction('attack')` 仍用数字 index 调 `autoCast(i)`

方案明确指出："autoCast 参数必须是 'A'|'B'|'C'|'D'|'E'，不是 0-4"

实际代码（combat_facade.js:181-186）：
```js
case 'attack': {
  for (let i = 0; i < 5; i++) {
    if (be.battleState.slotUnlocked[i] && be.battleState.cooldowns[i] <= 0) {
      be.autoCast(i);  // ← 传数字 0-4，但 autoCast 用 bs.chart[slot] 取技能
      return;
    }
  }
```

`autoCast(slot)` 内部做 `bs.chart[slot]`——chart 的键是 `'A'~'E'`，`bs.chart[0]` = `undefined`。

**功能影响**：高。如果玩家点击"攻击"按钮，此路径完全无效。但战诀核心循环不依赖此路径（引擎 `tick()` 内部用 `currentSlot` 字母正确调用 `autoCast`），所以自动战斗不受影响，只有手动"攻击"按钮失效。

### 方案要求：`combatAction('attack')` 不再尝试手动 `autoCast(i)`

方案建议：可记录"战诀会自行运转"或仅用于 legacy。
