## 2. V1.6 总目标

完成后必须满足：

1. 玩家有战诀时，点击可切磋 NPC 可以稳定进入新 BattleEngine，而不是旧战斗 fallback。
2. 五槽战诀开局全 CD。
3. 当前槽 CD 就绪且真气足够时自动出招。
4. 真气不足时出现 MP 门禁，玩家选择调息/服药/平斩/强行出招后战斗继续。
5. 技能数据字段统一，`mpCost` 与 `mana` 不再断裂。
6. 状态字段统一，毒/流血/火/冰能被引擎正确结算到 `shigu/lieshang/yehuo/ningyuan`。
7. 物理免疫不再失效，伤害类型明确。
8. 变式读取 `state.presetCharts`，不是不存在的 `state.chartPresets`。
9. 装备 v3 不强行完整接入，但要明确 V1.6 边界：只接基础武器数值和 1 个可验的规则型效果，或完全不接规则型效果并在 UI 隐藏相关暗示。
10. 增加自动测试，worker 不能只靠手点截图宣称完成。

## 3. 关键边界

### 3.1 战诀不是手动攻击

设计文档要求玩家战中不频繁点技能。战斗主循环是：

```text
战前配置战诀 -> 开战全槽读 CD -> 当前式双门禁通过 -> 自动出招 -> 推进下一式
```

所以不要新增“攻击”作为主要按钮。已有 `combatAction('attack')` 如果保留，只能作为调试或旧战斗 fallback，不得成为新战诀核心交互。

易错点：

- `CombatFacade.combatAction('attack')` 当前用数字 index 调 `be.autoCast(i)`，但 `autoCast` 需要 `'A'|'B'|'C'|'D'|'E'`。不要继续依赖这条路径。
- UI 上不要让玩家以为要疯狂点“攻击”。

### 3.2 数据适配优先于改数据源

`public/data/combat_skills_v3.js` 是生成数据，字段很多。不要手改 70 个技能来追引擎。应在运行时做统一适配。

必须新增或等价实现：

```js
normalizeCombatSkill(rawSkill)
```

输出字段至少包含：

```js
{
  id,
  name,
  slot,
  cd,
  mana,
  dmgType,
  skillNum,
  skillNumLvAdd,
  status: {
    shigu,
    lieshang,
    yehuo,
    ningyuan,
    pogang,
    mihun,
    nixue
  },
  effects,
  tags
}
```

字段映射规则：

```text
mana      = raw.mana ?? raw.mpCost ?? 0
dmgType   = raw.dmgType ?? raw.damageType ?? infer from tags/path/type
shigu     = raw.shiguNum ?? raw.duNum ?? 0
lieshang  = raw.lieshangNum ?? raw.bleedNum ?? 0
yehuo     = raw.yehuoNum ?? raw.burnNum ?? 0
ningyuan  = raw.ningyuanNum ?? raw.iceNum ?? 0
pogang    = raw.pogangNum ?? 0
mihun     = raw.mihunNum ?? 0
nixue     = raw.nixueNum ?? 0
```

伤害类型推断最低规则：

```text
tags 含 火系 -> fire
tags 含 冰系 -> ice
tags 含 毒系 -> poison
tags 含 血系 -> bleed
tags 含 spirit 或 path === 'ling' -> spirit
否则 -> physical
```

注意：推断只做兜底。若数据显式写了 `dmgType`，以显式字段为准。

### 3.3 `state.chart` 与 `state.presetCharts` 是唯一存档契约

现有存档字段：

```js
state.chart
state.presetCharts
```

不得新增并使用：

```js
state.chartPresets
state.charts
```

如果旧代码仍读 `chartPresets/charts`，要改成兼容读取，但写入统一写回 `presetCharts`。

推荐格式：

```js
state.chart = {
  id: "wenjian_basic",
  name: "问剑峰·入门五式",
  slots: { A: 1001, B: 1002, C: 1003, D: 1004, E: 1005 }
}
```

兼容旧格式：

```js
state.chart = { A: 1001, B: 1002, C: 1003, D: 1004, E: 1005 }
```

引擎入口必须统一使用：

```js
getChartSlots(state.chart)
```

不要在各文件里各自猜 chart 的形状。

`state.presetCharts` 推荐格式：

```js
state.presetCharts = [
  {
    id: "wenjian_basic",
    name: "问剑峰·入门五式",
    slots: { A: 1001, B: 1002, C: 1003, D: 1004, E: 1005 }
  },
  {
    id: "wenjian_fast",
    name: "问剑峰·快剑试式",
    slots: { A: 1001, B: 1002, C: 1002, D: 1003, E: 1005 }
  }
]
```

### 3.4 装备 v3 的 V1.6 边界

V1.6 不完整实现装备 v3。

只允许两种做法，选一种：

方案 A，保守推荐：

- 战斗只读取旧装备：
  - `state.equipment.weapon.atk`
  - `state.equipment.armor.def`
- 伤害公式修成：
  - `skillNum × (playerAtk + weaponAtk) - targetDef`
- 暂不展示装备规则型效果。
- 不接 `COMBAT_EQUIPMENT_V3`。

方案 B，小步接入：

- 把 `temp/work/combat_equipment_v3.js` 迁移到 `public/data/combat_equipment_v3.js`。
- manifest/data_loader 注册 `COMBAT_EQUIPMENT_V3`。
- 只实现 1 个问剑峰武器效果，例如游龙剑“三式一闪”。
- 必须有测试证明效果触发。

不允许：

- 半接 8 种武器但没有测试。
- UI 上展示一堆规则词条，但战斗里没结算。
- 为了装备 v3 大改背包系统。

### 3.5 Boss v3 的 V1.6 边界

V1.6 不完整做 Boss。

只做接口预留：

- BattleEngine 支持 `enemyData.chart`。
- UI 可以显示“敌方当前式/下一式”占位。
- 不迁移 `temp/work/combat_boss_v3.js`，除非同时做 manifest、data_loader、测试。

不要一边说 Boss 可预判，一边 UI 完全看不到敌方节奏。

### 3.6 畸变接口不能读错字段

存档字段是：

```js
state.corruptionLevel
```

旧代码有些读：

```js
state.corruption
```

V1.6 统一：

```js
getCorruptionLevel(state) {
  return state.corruptionLevel ?? state.corruption ?? 0;
}
```

写入统一写：

```js
state.corruptionLevel
```

不要继续新增 `corruption`。

## 4. 推荐实现顺序

### Step 1：建立 combat contract 工具层

新增文件：

```text
src/combat_contract.js
```

导出：

```js
export const COMBAT_SLOTS = ['A', 'B', 'C', 'D', 'E'];
export function normalizeCombatSkill(rawSkill) {}
export function getSkillCost(skill) {}
export function getSkillDamageType(skill) {}
export function getSkillStatusPayload(skill) {}
export function getChartSlots(chart) {}
export function normalizeChart(chart) {}
export function findPresetChart(state, chartId) {}
export function getCorruptionLevel(state) {}
export function setCorruptionLevel(state, value) {}
```

目的：

- 不要让 `battle_async.js`、`combat_facade.js`、`battle_intervene.js` 各自写一套兼容逻辑。
- 后续测试只测这个文件就能抓住 80% 字段错配。

验收：

- `normalizeCombatSkill({ mpCost: 8 }).mana === 8`
- `normalizeCombatSkill({ duNum: 3 }).status.shigu === 3`
- `normalizeCombatSkill({ burnNum: 2 }).status.yehuo === 2`
- `getChartSlots({ slots:{A:1} }).A === 1`
- `getChartSlots({ A:1 }).A === 1`

### Step 2：BattleEngine 改为只吃 normalized skill

修改：

- `src/battle_async.js`

要求：

- `getSkillData(skillId)` 返回 normalized skill。
- 所有 `sk.mana` 仍可用，但来源必须是 `mpCost/mana` 兼容后的结果。
- `_applyStatusEffects` 不直接读 `skill.shiguNum` 等旧字段，改读 `skill.status.shigu`。
- `getBattleUIData()` 的 `mpEnough` 和 `mpGate.need` 都走 `getSkillCost(skill)`。
- `calcSkillDamage` 接收 `weaponAtk`。

易错接口：

```js
checkDoubleGate(slot)
autoCast(slot)
triggerMpGate(skill)
resolveMpGate(choice)
getBattleUIData()
```

这些函数都必须使用同一套 `mana` 与状态字段。

验收：

- 将玩家 `mp` 设为 0，当前技能 `mpCost > 0`，必须进入 MP 门禁。
- 释放 `duNum > 0` 技能后，敌方 `enemyStatus.shigu > 0`。
- 释放 `burnNum > 0` 技能后，敌方 `enemyStatus.yehuo > 0`。

### Step 3：CombatFacade 只负责启动，不负责补丁式战斗

修改：

- `src/combat_facade.js`

要求：

- 启动战斗时使用 `normalizeChart`。
- 如果 `state.chart` 没有，但玩家有门派且有 `COMBAT_SKILLS_V3`，可生成默认战诀并写入 `state.chart`。
- 如果仍无战诀，不进入新 BattleEngine。
- `combatAction('attack')` 不再尝试手动 `autoCast(i)`。可记录“战诀会自行运转”或仅用于 legacy。

易错点：

- `autoCast` 参数必须是 `'A'|'B'|'C'|'D'|'E'`，不是 `0-4`。
- 不要每次开战都覆盖玩家已有 `state.chart`。
- 不要在无技能数据时静默 fallback，让测试误以为通过。

验收：

- 玩家已有 chart 时，startCombat 不覆盖 chart。
- 玩家无 chart 但门派是问剑峰时，能自动生成 A-E 五槽。
- 玩家无 chart 且无可生成数据时，给明确日志，不启动新战斗。

### Step 4：InterveneEngine 修复变式读取

修改：

- `src/battle_intervene.js`

要求：

- `_getPresetChart(chartId)` 从 `state.presetCharts` 数组读取。
- 兼容旧对象格式，但不要写回旧字段。
- `getAvailableInterventions()` 返回真实可用的变式列表。
- `doVariant(chartId)` 切换到 `preset.slots`，并重新扫描羁绊。

易错点：

- `state.presetCharts` 是数组，不是对象。
- 当前战诀与目标战诀相同，应提示但不消耗变式次数。
- MP 门禁中不能变式。

验收：

- `presetCharts=[{id:'alt', slots:{...}}]` 时，`doVariant('alt')` 成功。
- 变式后 `battleState.chart` 等于目标 slots。
- 第二次变式失败，且不改变 chart。

### Step 5：NPC 切磋入口修正

修改：

- `src/npc_service.js`
- 必要时 `src/perception_service.js`

要求：

- `canSpar` 只表达 NPC 是否允许切磋，不表达玩家是否已有战诀。
- 玩家缺战诀时，点击切磋应尝试生成默认战诀；仍失败才提示。
- 引路 NPC 如苏小棠保持不可切磋。

易错点：

- 不要再用 `dl.XINGGONG && dl.XINGGONG[s.faction]` 判断玩家有无战诀。`XINGGONG` 结构不是按门派名直接索引。
- 不要把所有 NPC 都可切磋。`guide/recruiter` 类型应禁用。

验收：

- 值星弟子显示切磋。
- 苏小棠不显示切磋。
- 点击值星弟子切磋进入新 BattleEngine。

### Step 6：数值最小对齐

修改：

- `src/battle_async.js`
- 必要时 `src/game.js`

要求：

- 玩家战斗属性计算至少包含：
  - `state.attack`
  - `state.defense`
  - `state.maxHp`
  - `state.maxMp`
  - `state.equipment.weapon.atk`
  - `state.equipment.armor.def`
- 伤害公式最小实现：

```js
damage = skillNum * (atk + weaponAtk) - targetDef
```

- `maxMp` 不要硬编码长期停留在 80；若当前境界表没有 mp 字段，可以 V1.6 先保留现状，但必须测试 MP 门禁能触发。

易错点：

- `combat_numerics_v3.md` 的完整大数值不要求本阶段全部迁移。
- 但不能让 `mpCost` 无效，否则战诀核心失效。

验收：

- 装备武器 `atk: 10` 后，同技能伤害高于无武器。
- 物理技能打 `physicalImmune: true` 敌人伤害为 0。
- 火/冰/毒/血/灵压技能打物理免疫敌人不被强制归 0。

### Step 7：UI 最小表达

修改：

要求：

  - 当前式高亮

- UI 不能只显示血条，看不见战诀节奏。
- 当前式和 READY 是不同状态，别混成同一个颜色。

验收：

- 开战 0 秒时五槽都有 CD。
- 最短 CD 到时自动出招，日志出现技能名。
- MP 不足时，当前式显示门禁态。

## 6. 常见误区清单

### 误区 1：直接改 70 个技能数据

不要这么做。应该做字段适配层。

### 误区 2：把 `XINGGONG[s.faction]` 当门派战诀

不要这么做。`XINGGONG` 的结构是 `slots/charts/bossCharts/...`，不是按门派名直接索引。

### 误区 3：把装备 v3 一口气接完

不要这么做。V1.6 的目标是战诀契约稳定，不是装备大版本。

### 误区 4：继续加 UI 按钮绕过核心循环

不要新增“手动释放 A/B/C/D/E”。战诀是自动运转，玩家只干预。

### 误区 5：只测入口，不测门禁

门禁是战诀核心之一。必须构造低 MP 场景测到 MP 门禁。

### 误区 6：只测伤害，不测状态

异常状态是 build 空间。至少测毒/流血/火/冰任意两个字段映射。

### 误区 7：把乱码当本次任务

部分旧生成数据注释或文本有编码乱码。V1.6 不处理大规模乱码清洗。只处理影响运行的字段。

## 7. 推荐提交粒度

建议拆成 4 个小提交或 4 个阶段日志：

1. `combat contract: normalize skill/chart fields`
2. `battle engine: apply normalized cost/status/damage`
3. `combat flow: fix presets and npc spar entry`
4. `tests: add V1.6 combat contract coverage`

如果 worker 不能提交 git，至少按这 4 段写开发日志。

## 8. 完成后的下一步

V1.6 通过后，才能进入：

- V1.7 战斗 UI 风格化
- V1.8 装备 v3 最小可玩闭环
- Figma 控件库整理

在 V1.6 之前，不建议画完整战斗页。否则 UI 会绑定错误的数据结构和错误的战斗交互。
